# Dawn × Minimals — Phase 2 (Homepage) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the homepage `ct-*` Liquid sections (hero, hero-split, marquee, stats, trust-bar, A+ banners, use-cases, reviews, FAQ, compare, before/after, email) + a dismissible `ct-announce` bar, all faithfully translated from `dawn-design-system.html`, then wire them into `templates/index.json` and the header group.

**Architecture:** New schema-driven `sections/ct-*.liquid` units (Layer 3 of the spec). Each section loads a shared `assets/ct-sections.css` (button family, eyebrow, section-head, rating row, grid helpers) plus its own `assets/section-ct-<name>.css`, follows Dawn's per-section padding pattern, and exposes a `color_scheme` setting. **All commerce stays frozen** — these are new marketing sections; no Dawn JS or commerce snippet is touched. Behavior (reveal-on-scroll, count-up, accordion, swipe, before/after drag) is provided by the 8 vanilla JS utilities already loaded globally in P1 — sections only emit the `data-*` hooks those utilities consume.

**Tech Stack:** Shopify Liquid, CSS custom properties (`--ct-*` tokens from `snippets/css-variables.liquid`), the P1 vanilla JS utilities (`ct-reveal.js`, `ct-countup.js`, `ct-swipe.js`, `ct-accordion.js`, `ct-ba.js`), Shopify CLI (`shopify theme dev` / `theme check`).

**Spec:** `docs/superpowers/specs/2026-05-24-dawn-minimals-theme-design.md`. **Foundation contract:** `docs/superpowers/plans/2026-05-24-foundation-p0-p1.md` (the `--ct-*` tokens, `.ct-*` classes, and JS `data-*` hooks defined there are the API this plan builds on). Read both before starting.

## Domain note: how "tests" work here

This is a Liquid/CSS/JS theme — there is no unit-test runner. Each task's verification is the theme's real quality gate, in this order:

1. **`shopify theme check`** → must be clean (no new offenses). Confirm balanced Liquid (no unclosed `{% if %}`/`{% for %}`/`{% schema %}`).
2. **Live preview** via `shopify theme dev` → in the Theme Editor, **Add section → "CT <name>"**, confirm the stated visual/behavioral expectation, and check the browser console for zero errors.
3. **Commit.**

No P2 task touches a commerce snippet, so the per-task commerce smoke-test is **not** required mid-phase; it is run once at the **phase gate**. Run `shopify theme dev` once in a side terminal and leave it running; it hot-reloads on save. The storefront is password-protected — ask the user for the password and pass `--store-password` (dev store `pwsirj-4x.myshopify.com`).

**Branch:** All P2 work continues on **`feat/minimals-foundation`** (per the resume decision — Foundation is NOT merged to `master`; all theme work accumulates on this branch). Verify with `git branch --show-current` → `feat/minimals-foundation` before starting.

## Token & class rename quick-reference

Every component below is ported from `dawn-design-system.html`. The demo CSS uses **bare token names** and some **bare class names**; the port does a mechanical find-replace. The plan already shows the renamed result in each task, but use this table to verify:

**Tokens (demo → `--ct-*`, all already emitted by `snippets/css-variables.liquid`):**

| demo | `--ct-*` | demo | `--ct-*` |
|---|---|---|---|
| `--bg-base` | `--ct-bg` | `--brand` | `--ct-accent` |
| `--bg-layer` | `--ct-bg-surface` | `--brand-rest` | `--ct-accent-strong` |
| `--bg-elevated`/`--bg-card` | `--ct-bg-raised` | `--brand-fg` | `--ct-accent-text` |
| `--bg-control` | `--ct-bg-control` | `--brand-bg2` | `--ct-accent-subtle` |
| `--tx1`/`tx2`/`tx3`/`tx4` | `--ct-text`/`-2`/`-3`/`-off` | `--brand-str` | `--ct-accent-border` |
| `--str1`/`str2`/`str3`/`str4` | `--ct-border`/`-strong`/`-subtle`/`-faint` | `--error-main` | `--ct-error` |
| `--sh2`/`sh4`/`sh8`/`sh16`/`sh28` | `--ct-shadow-xs`/`sm`/`md`/`lg`/`2xl` | `--r-s`/`r-m`/`r-l`/`r-xl`/`r-pill` | `--ct-r-sm`/`md`/`lg`/`xl`/`pill` |
| `--font` | `--ct-font-body` | `--mono` | `--ct-font-mono` |
| `--focus` | `--ct-focus` | `--ct-price`/`--ct-rating`/`--ct-touch` | kept as-is |

> ⚠ Note the `--str*` ordering: `--ct-border` is the **strongest** (.32 alpha), `--ct-border-strong` is .20, `--ct-border-subtle` is .12, `--ct-border-faint` is .06. This matches what P1 emitted — do not "fix" it.

**Classes (spec §5 — demo bare names that collide with Dawn or need namespacing → `ct-`):** `.announce*`→`.ct-announce*`, `.trust-*`→`.ct-trust-*`, `.review-*`→`.ct-review-*`, `.faq-*`→`.ct-faq-*`, `.compare-table`/`.cmp-*`→`.ct-compare`/`.ct-cmp-*`, `.ba-*`→`.ct-ba-*`, `.aplus-*`→`.ct-aplus-*`, `.rev-*`→`.ct-rev-*`, `.use-case-*`→`.ct-use-case-*`, `.btn*`→`.ct-btn*`. Classes the demo already namespaced (`.ct-marquee*`, `.ct-stat*`, `.ct-hero*`, `.ct-email*`, `.ct-eyebrow`) are kept.

**JS hooks (from P1 — emit these `data-*`, do NOT write new JS for them):**
- `ct-reveal.js` → `[data-reveal]` (optional `data-delay="<ms>"`); CSS base `[data-reveal]{opacity:0;transform:translateY(20px)}` + `.is-visible` already in `theme-overrides.css`.
- `ct-countup.js` → `[data-countup][data-to="<int>"][data-suffix="<str>"]`; animates `0→to`. `data-to` must be an integer.
- `ct-accordion.js` → container `[data-accordion]`, each trigger `[data-accordion-btn]` with `aria-expanded`, panel = the trigger's **next element sibling** (JS controls its `max-height`).
- `ct-swipe.js` → `[data-swipe]` (drag-to-scroll on an overflow-x container).
- `ct-ba.js` → root `[data-ba]` containing `.ct-ba-after` + `.ct-ba-handle` (JS sets `clip-path` + handle `left`).

    (function () {
      var bar = document.getElementById('ct-announce-{{ section.id }}');
      if (!bar) return;
      try { if (sessionStorage.getItem('ct-announce-dismissed') === '1') { bar.style.display = 'none'; return; } } catch (e) {}
      var msgs = bar.querySelectorAll('.ct-announce__msg'), i = 0;
      var reduced = window.matchMedia('(prefers-reduced-motion:reduce)').matches;
      if (msgs.length > 1 && !reduced) {
        setInterval(function () {
          msgs[i].classList.remove('is-active');
          i = (i + 1) % msgs.length;
          msgs[i].classList.add('is-active');
        }, {{ section.settings.rotate_seconds | default: 4 | times: 1000 }});
      }
      var x = bar.querySelector('.ct-announce__dismiss');
      if (x) x.addEventListener('click', function () {
        try { sessionStorage.setItem('ct-announce-dismissed', '1'); } catch (e) {}
        bar.style.display = 'none';
      });
    })();
  </script>
{%- endif -%}

## Notes for later phases

- **Reused contract:** every section emits only the P1 JS `data-*` hooks (`data-reveal`, `data-countup`, `data-accordion`, `data-swipe`, `data-ba`) and `--ct-*` tokens — no new global JS was added in P2. PDP/collection phases extend the same vocabulary.
- **`ct-sections.css` shared file** is the home for cross-section primitives. P3 (PDP) can reuse `.ct-btn`, `.ct-eyebrow`, `.ct-section-head`, `.ct-rating-row`, and `ct-aplus` (the A+ banner pattern serves PDP feature banners too).
- **Section CSS-loading pattern** (`{{ 'ct-sections.css' | asset_url | stylesheet_tag }}` + per-section file at the top of each `.liquid`) is the convention for all future `ct-*` sections.

### Deferred (revisit at the P5 QA/Lighthouse gate)
1. **Review Carousel (T+ demo group).** P2 ships `ct-reviews` as a desktop grid + mobile swipe rail (the lean option). The demo's full carousel — dot pagination, prev/next arrows, 4s autoplay — was deferred. If wanted, add it as a `layout: carousel` variant with a ~40-line scoped script (the demo's `#revCarousel` script, ct-namespaced) rather than a global util.
2. **Duplicate `<link>` for `ct-sections.css`.** Each `ct-*` section emits its own `<link>` to the shared file; the browser dedupes by URL (harmless) but Lighthouse may flag repeated tags. At the perf pass, consider rendering shared section CSS once from `theme.liquid` (like `theme-overrides.css`) or folding `ct-sections.css` into `theme-overrides.css`.
3. **A+ `:nth-child` divider rules on `ct-stats`** assume a 4-stat layout; with 5–6 stats the mobile dividers are approximate. Revisit if a merchant uses a non-4 count.
4. **`ct-aplus` specs are a comma-split string.** Commas inside a spec value will split incorrectly. If merchants need commas, switch to discrete `spec_1..spec_4` block fields.
5. **Slot copy → locale keys.** Section default strings are English (consistent with the P1 foundation slots). Move user-facing defaults to `locales/en.default.json` before any non-English storefront (same deferral as the P1 cart slots).
6. **`forced-color-adjust:none`** (P1 light-lock) still applies — re-confirm the Windows High-Contrast tradeoff at the final a11y gate.
